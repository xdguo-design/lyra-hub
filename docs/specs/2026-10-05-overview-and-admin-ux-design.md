# 总览加载与管理页面体验修复设计

## 目标

减少 Hub 总览受慢速平台探测影响的等待，整理 Gateway 连接表单，并确保未通过平台管理员鉴权时租户写操作不可用。

## 已观察到的问题

- `App.refreshCore` 将 Registry 数据与 Gateway、Agents 健康探测放进同一个 `Promise.all`，导致慢速上游阻塞应用数据呈现。
- Gateway 表单把“明确移除已保存凭据”作为整行网格字段渲染，复选框和说明分离，破坏操作区域的视觉关联。
- `TenantsPage` 加载租户失败并提示 401/403 后，仍展示创建表单，造成“无权访问”与可操作界面并存。

## 设计

1. 将总览数据和平台状态请求分离。应用、导航和 Hub 健康数据完成后立即更新总览；Gateway 与 Agents 状态独立更新。平台状态请求失败时保留页面主体，不覆盖总览错误提示。
2. 将 Gateway 凭据清除选项放入明确的凭据操作行，使复选框与说明保持并列；桌面和窄屏均可读。
3. 租户管理页面默认处于未确认权限状态。租户读取成功后开放创建、停用和邀请操作；遇到 401/403 时隐藏写操作并展示获取权限的提示。其他错误保持错误态，不开放写操作。保存管理员令牌后重试租户读取。

## 验收标准

- 延迟未完成的 `/api/v1/platform/status` 不阻塞应用卡片和 Hub 健康状态渲染。
- Gateway 凭据清除复选框与其说明在同一可读操作组内，响应式布局不产生横向溢出。
- 租户读取成功前、以及读取返回 401/403 时，不显示租户写操作；成功后现有创建、停用和邀请行为保留。
- 前端测试、构建和后端现有测试通过；在浏览器重新观察对应页面。

## 范围与约束

仅修改 Hub 前端总览、Gateway 表单和 Agents 租户视图及其测试。保留仓库现有未提交改动，不改 Hub API 合约、认证策略、后端服务或业务数据。
