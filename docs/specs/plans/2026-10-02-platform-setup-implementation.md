# Lyra Hub P0 平台连接实施计划

## 目标

落实 Hub PRD 的 Gateway 与 Agents 管理页面和真实接口交互，并修正跨项目能力的可用性声明。保持各项目独立入口与数据所有权。Agent 执行、Workflow 执行、Narrative AI 完整中转和 Narrative 到 Print 的业务流依赖尚未发布的身份／执行契约，不在本次伪造为已完成能力。

## 任务

1. **连接 API 与安全（已完成）**：持久化 Gateway／Agent OS 的 URL、Fernet 加密凭据、修订号、最近检查及最近可用版本；检查草稿、保存、恢复和清除；使用管理令牌保护配置写入和高风险能力调用；浏览器只收到凭据状态。
2. **真实能力状态（已完成）**：Hub 页面核验 Gateway 健康与模型目录、Agent OS 健康与 Agent 目录；未知／空目录与认证／网络错误分开；Agent／Workflow 执行 API 未发布时返回 501 并标为不可用。
3. **Hub 页面（已完成）**：增加 Gateway、Agents 专属页面，支持配置检查／保存／恢复、目录刷新、用户显式生成检查，并呈现配置来源、凭据状态、能力状态、错误和空目录。总览改为真实健康状态。
4. **Print 能力契约（已完成）**：增加 `/api/lyra/capabilities/print.execute`，将正式任务创建、排队和幂等键记录放入一个事务；相同请求重放返回原任务，键冲突返回 409；更新 OpenAPI 和 Hub 适配器。
5. **验证（已完成）**：Agents、Gateway、Narrative、Print 的完整 Python 测试分别通过；Hub 后端完整测试通过（Windows 缺少符号链接权限时跳过对应用例）；Hub、Agents 前端构建及 Gateway Web 测试／构建通过。

## 验收

- Hub 重启后仍能恢复已保存的连接设置；密钥不明文落库或返回浏览器。
- 未配置管理令牌时，管理与可能收费／产生副作用的操作失败关闭；匿名用户不能直接调用生成。
- 目录显示与真实上游响应一致；有效空目录不等于连接失败。
- Agent OS 没有执行 HTTP 契约时，Agent／Workflow 执行明确不可用。
- 每个仓库的相关检查通过，或在结果中明确指出环境依赖与失败原因。

## 仍未交付的上游依赖

- Agent OS 的 `agent.run`、`workflow.run` 执行契约及认证／生命周期尚未发布；Hub 已将这两个入口显式禁用。
- Hub 当前管理员认证为部署级共享令牌，正式用户身份、租户隔离和公网授权仍需独立设计。
- Narrative 对已确认稿件的业务打印流程仍未完成；底层 Print 幂等能力接口不能替代稿件选择、确认和授权流程。
