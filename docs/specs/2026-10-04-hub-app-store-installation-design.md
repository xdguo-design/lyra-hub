# Hub 应用商店与连接器安装设计

**状态：待用户审阅**  
**日期：** 2026-10-04

## 1. 目标

将 Lyra Hub 从“已登记应用的入口与配置面板”扩展为应用商店：用户打开 Hub 后能发现、下载、安装、更新和打开应用；模型与平台接入以连接器插件的方式添加，并由向导完成授权和健康检查。

此设计沿用业务应用可独立运行的原则。安装进 Hub 不得成为应用运行或保存业务数据的前提。

## 2. 当前基线

- 应用中心从已有 Manifest Registry 读取应用并支持启用、配置、启动；没有应用目录、下载、安装、更新或卸载流程。
- 插件中心读取本地插件清单，支持启用和权限授权；没有插件包安装与版本管理。
- Gateway 和 Agents 的平台连接页要求输入服务地址和凭据。Hub 管理操作另外要求浏览器提交与后端环境变量 `LYRA_HUB_ADMIN_TOKEN` 相同的共享令牌。
- Hub 目前可通过 iframe + Workspace Context Bridge 打开 Narrative；本设计保留该集成方式。

## 3. 用户体验

Hub 默认打开“发现”页，提供“应用”“连接器”“已安装”“更新”筛选：

- **应用**：展示 Lyra Narrative、Print、Agents、Gateway 等由目录发布的应用条目，列出说明、版本、发布者、下载来源、运行要求和权限。
- **连接器**：展示模型提供商与平台集成。连接器只负责连接远程服务，不代表将远程模型权重下载到本机。
- **已安装**：展示安装状态、版本、健康状态和“打开”“更新”“停用”“卸载”操作。
- **更新**：展示可用版本与变更摘要，由用户发起更新。

用户打开条目后看到详情和权限说明，点击“安装”后由 Hub 下载并校验包、安装、登记、检查健康状态。健康检查通过后条目进入“已安装”，应用可从 Hub 打开。失败时撤销本次安装产生的文件和登记，不影响现有业务数据。

卸载默认只移除应用包和 Hub 登记，保留用户数据；清理数据是单独的、明确的操作。应用停用、卸载、更新均写入审计记录。

## 4. 目录与安装架构

### 4.1 可信目录

- MVP 使用 Lyra 维护的单一官方目录，目录清单托管在 GitHub；应用 OCI 镜像和连接器版本资产使用用户提供的 GitHub 仓库 Release 下载地址。暂不支持任意第三方目录或用户上传包。
- 目录条目采用版本化 Manifest，包含 ID、版本、显示信息、发布者、GitHub 仓库与固定 Release 资产 URL、包类型、SHA-256、系统要求、健康检查、权限、升级与卸载策略。目录固定具体版本和资产，不使用 `main`/`master` 分支、latest 别名或仓库源码归档作为安装包。
- 官方目录根公钥随已签名的 Hub 安装包提供，是首次信任根。目录由该根密钥签名；签名目录固定每个 GitHub Release 资产的 URL、SHA-256 和 OCI image digest，下载内容必须逐项匹配。
- 根密钥轮换必须由当前根密钥签名新根公钥和生效版本；目录携带签名撤销列表，Hub 在下载和安装时拒绝撤销或过期密钥。根密钥紧急撤销通过新的签名 Hub 发布包分发。
- Hub 先验证目录签名，再下载包。校验失败、目录签名密钥撤销或系统要求不满足时拒绝安装。
- 目录、安装记录、版本与运行状态存入 Hub 数据库；下载缓存不保存凭据。

### 4.2 安装器

- Hub 后端只调用内置、按包类型注册的安装适配器，不执行 Manifest 提供的任意 shell 命令或脚本。
- MVP 应用包为 GitHub Release 附件中的 OCI 镜像归档（OCI/Docker archive），目录固定附件 URL、版本、SHA-256 和镜像 digest。Hub 下载并校验归档，再通过 Docker Compose 适配器加载、启动、更新和停止；安装前检查 Docker Engine。运行环境缺失时展示安装说明和官方来源，Hub 不静默安装系统运行时。
- OCI 容器默认非特权、非 root、只读根文件系统、丢弃全部 Linux capabilities，不使用 host network、host PID/IPC、设备映射或 Docker socket；唯一持久挂载是该应用独立数据目录。只开放 Hub 反向代理和健康检查所需端口；容器仅可访问声明的 Hub/Gateway 目标。Manifest 申请超出默认范围的权限时展示差异并要求管理员逐项授权；MVP 拒绝特权容器和主机路径挂载申请。
- Provider API Key 不注入应用容器；小说应用只拿到其 Gateway 应用凭据，模型请求仍通过 Gateway 路由。
- 已独立运行的服务可通过目录声明的固定本机端口和健康端点被发现并“连接”；此模式只登记入口，不由 Hub 管理服务生命周期，也不要求用户手工填写 URL。条目明确区分“已安装（Hub 管理）”和“已连接（外部运行）”。
- 连接器插件 MVP 为声明式 Manifest，由 Hub 内置连接适配器实现连接逻辑；插件包不得携带可执行代码。
- 首批支持 Lyra 官方 OCI 应用与连接器。现有 Narrative 等独立服务可先以“连接外部运行服务”接入；后续发布 OCI 包后可从已连接切换为 Hub 管理安装。
- 应用持久数据存放在 Hub 为该应用创建的独立主机目录，不依赖 Docker 卷快照 API。更新前停止容器并等待退出，检查可用磁盘空间后复制该目录到带版本号的快照目录并校验 SHA-256；空间不足或快照校验失败时拒绝更新。
- 更新期间先在隔离端口启动新镜像并执行显式版本化数据迁移和健康检查，确认成功后切换 Hub 路由并恢复服务。失败时停止新镜像，将快照目录恢复为活动数据目录，再启动旧镜像；失败期间不向用户流量开放新镜像。
- 应用 Manifest 声明数据 schema 版本和支持回退的版本范围。若迁移超出回退范围，Hub 必须保留完整快照并显示恢复影响，禁止自动删除旧版本和快照。
- 快照保留至该应用下一次成功更新或用户明确删除。卸载不触碰应用数据目录；删除数据是单独的、明确确认操作。

## 5. 连接与授权

- 已知的本机 Lyra 服务由连接器根据安装包的服务声明发现地址，并执行健康检查。用户不需要复制粘贴服务 URL。
- 支持 OAuth 或设备授权的服务通过连接器启动授权流程，使用最小权限 scope；连接完成后返回 Hub 并显示账号、权限和连接状态。
- Hub 到 Agents 使用独立的服务身份，不复用 Hub 管理员会话或人类用户访问令牌。首次连接时 Hub 显示短时有效的配对码；管理员在 Agents 登录页登录并确认 Hub 名称及申请的最小 scope。Agents 一次性签发服务凭据，Hub 后端直接接收并存入系统凭据库，浏览器只看到配对状态。
- Agents 服务凭据默认只允许读取 Agent 目录与连接健康状态。租户管理等写权限必须在 Agents 授权页单独勾选；凭据有到期时间，可在 Agents 管理页撤销或重新配对。令牌失效时 Hub 显示“重新连接”并重新走配对流程。
- Hub 到 Gateway 同样采用 Gateway 管理页批准的配对流程：Hub 展示短时配对码，管理员在 Gateway 登录并批准 Hub 身份。Gateway 签发专属、可撤销的服务凭据，最小 scope 限于 provider connection 的创建/验证/模型发现；不授予租户管理、配额修改或 Gateway 管理权限。Hub 后端将凭据存入系统凭据库，浏览器只收到配对状态。
- Hub 调用 Gateway Provider 管理 API 时使用上述服务身份；API Key 仅在创建连接的单次请求中转发，Gateway 保存供应商凭据并返回 connection ID、模型 ID 和健康状态。Gateway 管理员可随时撤销 Hub 身份；过期或撤销后向导停止并提示重新配对。
- 只支持 API Key 的服务需要一次性授权输入。输入使用遮蔽字段，并由 Hub 后端在内存中短暂接收后立即转发到 Gateway 的受保护 Provider 管理 API；Key 仅由 Gateway 保存到其凭据库。Hub 数据库只存 Gateway connection ID 和模型元数据，浏览器存储、Hub API 响应、日志和审计内容均不包含密钥。
- dots3、ATRIA、agnes 作为 Gateway 连接器呈现。连接器不直接调用模型供应商：Hub 的向导把一次性 Key 交给 Gateway，Gateway 验证并保存凭据、发现模型；Narrative 仍通过 Gateway 的应用凭据路由模型请求。Hub 不要求用户维护共享的 Hub 管理令牌。
- 若 Gateway 当前不提供受保护的 Provider 管理 API，必须先实现该最小契约，再开放 Hub 连接器向导；禁止改由 Hub 长期保存 Provider Key。
- 授权完成后，Gateway 自动验证连接并列出远端可用模型。权限/用量政策显示在连接确认页。模型生成费用按 Gateway 供应商实际计费；连接测试使用最小请求并清楚提示潜在费用。

## 6. Hub 管理身份

- 移除常规管理操作中对 `LYRA_HUB_ADMIN_TOKEN` 与浏览器 `sessionStorage` 令牌的依赖。
- 本机首次启动时进入初始化向导，创建本机 Hub 管理员账号；后续操作使用服务端签发的短期会话和 `HttpOnly`、`Secure`（适用时）、`SameSite` Cookie。状态变更校验 CSRF，并使用本机管理员角色授权。
- 非本机部署使用预配置身份提供方；MVP 不开放匿名远程初始化，也不支持共享管理员令牌登录。
- Hub 到 Gateway/Agents 的服务凭据与人的 Hub 登录凭据分离。服务凭据只由连接器保存到系统凭据库并在后端使用，不传给浏览器。
- Agents 配对凭据由 Agents 签发和撤销，Hub 只持有短期、最小 scope 的服务身份。管理员可从 Agents 管理页撤销连接；失效后目录访问停止，不回退到共享用户令牌。
- Gateway 配对凭据由 Gateway 签发和撤销，scope 仅能由 Gateway 管理员在批准页授权；失效后连接器不能创建或管理模型连接，不回退到 Gateway 管理员令牌。
- 迁移现有部署时，保留现有 `LYRA_HUB_ADMIN_TOKEN` 兼容期：初始化本机管理员后禁用旧令牌入口，并提示管理员移除旧环境变量。不得静默把旧令牌转存为用户密码。

## 7. 权限、安全与失败处理

- 安装详情展示发布者、权限、运行要求和下载来源；首次安装及新增权限都需要管理员确认。
- 安装包只从签名目录声明的固定 GitHub Release URL 获取，并校验目录中签名的摘要。拒绝路径穿越、解包符号链接逃逸、文件覆盖到安装目录之外和未授权包类型。
- 安装、更新和授权采用显式状态：`available → downloading → verifying → installing → health_check → installed`；失败状态展示原因并提供安全重试。
- 安装失败清理本次创建的临时文件和登记；保留原有已安装版本与数据。连接失败不保存未验证的连接状态。
- OCI 更新和数据迁移遵循快照/回滚策略；回滚会明确显示数据时间点和潜在写入损失，不在不能安全回退时覆盖数据。
- 容器启动配置拒绝特权模式、Docker socket、host 网络和未授权主机挂载；测试确认 Provider Key 不进入容器配置或环境变量。
- Agents 配对需要 Agents 管理员授权；未授权或已撤销的 Hub 服务身份无法读取 Agent 目录，授权 scope 不能被 Hub 自行扩展。
- 令牌/密钥不进入 URL、浏览器 local/session storage、错误正文、审计 payload 或普通日志。

## 8. 分阶段范围

1. **目录与发现页**：定义签名目录和 Manifest；Hub 首页展示“发现/已安装/更新”，提供搜索和详情页；此阶段只读，不触发安装或授权。
2. **身份与配对基础**：先完成本机管理员初始化、Cookie 会话和 CSRF；再实现 Gateway/Agents 的短时配对、最小 scope、凭据库保存、撤销和重连。
3. **连接器向导**：已知 Lyra 服务发现、OAuth/设备授权、API Key 本机安全输入、Credential Manager 保存、模型发现和连接状态；使用第 2 阶段建立的服务身份。
4. **安全安装基础**：官方应用 OCI 包、签名校验、容器隔离、健康检查、数据目录快照、升级回滚和保留数据的卸载。

每一阶段可独立验收；连接器向导依赖身份与配对基础，应用安装依赖签名目录和安全安装适配器。dots3、ATRIA、agnes 在连接器向导完成后接入，不要求先完成 OCI 应用安装。

## 9. 成功标准

- 首次打开 Hub 显示可发现的官方应用和连接器；用户可区分可安装、已安装和可更新条目。
- 有 Docker Engine 时，从目录安装一个测试 OCI 应用后，Hub 显示版本和健康状态，并能打开应用；缺少 Docker 时给出官方安装说明。损坏签名包被拒绝，安装失败不破坏已安装版本或业务数据。
- 能发现目录已声明端口上的健康外部服务，并登记为“已连接”，不尝试接管其进程。
- 测试升级包的迁移失败时停止新镜像、恢复 SHA-256 校验通过的数据目录快照并启动旧版本。
- 容器缺少安全的默认隔离配置时拒绝启动；Manifest 申请特权容器或主机路径挂载时拒绝安装。
- 连接一个官方连接器不需要手工填写服务 URL；授权结束后 Hub 能显示健康状态与可用模型。
- API Key 只在本机一次性授权 UI 输入并交给 Gateway 凭据库；Hub 数据库、浏览器存储、API 响应、日志和审计记录中均无法读取密钥。
- Agents 服务身份需在 Agents 登录页配对批准；只授予所选 scope，撤销后 Hub 立即失去对应访问能力。
- Gateway 服务身份需在 Gateway 管理页配对批准；Provider API Key 只能通过最小 scope 的连接操作写入 Gateway，不可用于租户、配额或全局管理操作。
- 本机 Hub 首次管理员初始化后，管理操作不再要求用户填写 `LYRA_HUB_ADMIN_TOKEN`；未登录的状态变更被拒绝。
- Narrative 仍可独立运行；Hub 的安装或升级故障不影响其已有数据。

## 10. 非目标

- MVP 不提供任意第三方插件上传、执行任意插件代码或公开插件市场。
- Hub 不下载远程模型权重；Gateway 继续负责路由、配额、费用和模型调用。
- MVP 不实现 Agents Workflow 执行编排，也不改变 Agents 对租户和 Agent 运行权限的治理模型。
- 不自动替用户创建供应商账号、接受供应商协议或购买套餐。

## 11. 主要权衡

- 可信目录和固定包适配器限制了早期包格式的灵活性，但减少了远程代码执行面，适合先发布 Lyra 自有应用。
- API Key-only 供应商仍需要一次人工授权输入；用系统凭据库、连接器和向导取代复制令牌、编辑配置和浏览器长期保存。
- 从部署级共享令牌迁移到本机管理员会话涉及 Hub API 认证与部署初始化，不应和目录 UI 混为一次小改动；按阶段交付并保留兼容迁移路径。
